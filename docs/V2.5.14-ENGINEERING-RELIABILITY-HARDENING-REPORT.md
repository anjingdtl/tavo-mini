## 6. `GITHUB_RUN_NUMBER` 根因

```ts
// 修复前（V2.5.13）
const explicitBuildSource = process.env.SHINE_WRITER_BUILD_NUMBER
  ?? process.env.GITHUB_RUN_NUMBER;
```

GitHub Actions 的 `GITHUB_RUN_NUMBER` 是仓库级单调递增整数，**必然**会超过 99。一旦超过，`build > 99` 触发：

```text
SHINE_WRITER_BUILD_NUMBER must be an integer from 0 to 99; received <run_number>
```

而 `.github/workflows/verify.yml` 的 Android Debug Job 在 `assembleDebug` 之前执行 `npm run prebuild`（即 `node scripts/generate-version-json.js`），于是该 Job 在第 100 次 run 之后**必然**失败。本地构建不受影响（本地不设置 `GITHUB_RUN_NUMBER`），所以问题在 CI 才暴露。

## 7. 版本生成修复

```ts
// 修复后（V2.5.14）
const explicitBuildSource = process.env.SHINE_WRITER_BUILD_NUMBER;
let buildSource = explicitBuildSource ?? '0';
// ...（previous-version 保留逻辑不变）
const build = Number(buildSource);
if (
  !/^-?\d+$/.test(String(buildSource))
  || !Number.isInteger(build)
  || build < 0
  || build > 99
) {
  throw new Error(
    `SHINE_WRITER_BUILD_NUMBER must be an integer from 0 to 99; received ${buildSource}`,
  );
}
```

要点：

- 不再读取 `GITHUB_RUN_NUMBER`；
- 普通本地/CI 构建默认 `0`；
- 只有显式 `SHINE_WRITER_BUILD_NUMBER` 时才使用 0–99 后缀；
- 非整数 / 负数 / >99 继续报错（且 `/^-?\d+$/` 先行校验，`abc` 这类不再被 `Number()` 静默转成 `NaN/0`）；
- `versionCode` 单调递增、不依赖 Git 历史深度的既有约束保持不变；
- 正式发布版基础 `versionCode` 不变（`2051400 = 2*1_000_000 + 5*10_000 + 14*100 + 0`）。

## 9. Checkpoint eligibility reason 数据流

```text
prepareStoryMemoryForGeneration()
  └─ resolveUsableCheckpointForTarget(record, currentChapter.position)
       └─ CheckpointEligibilityResult {
            usable, reason,
            checkpoint,
            checkpointThroughPosition,   // coverage 起点（usable 时 = through，否则 -1）
            targetChapterPosition,        // ← 新增
            originalThroughPosition,      // ← 新增（即使不可用也保留原始 through）
            originalStatus,               // ← 新增（clean/dirty/empty/rebuilding/failed/null）
          }
  └─ PrepareStoryMemoryResult {
       checkpoint,                        // usable 时 = eligibility.checkpoint，否则 null
       checkpointEligibility,             // ← 新增（同一次判断的快照）
       coverage, checkpointUpdated, blocked, blockReason,
     }

buildContext()
  ├─ prepared = await prepareStoryMemoryForGeneration(...)   // 唯一一次 DB 读
  ├─ renderPreparedStoryMemoryContext(..., prepared.checkpoint, ...)
  │    └─ 内部仅对传入快照重新跑 eligibility（不读 DB），用 describeCheckpointEligibility 生成 trace reason
  └─ story_memory trace 推送：
       const eligibility = prepared?.checkpointEligibility;
       const checkpointReason =
         eligibility && !eligibility.usable
           ? describeCheckpointEligibility(eligibility)   // 真实原因
           : checkpointPos >= 0
             ? `检查点截至第 ${checkpointPos + 1} 章`
             : '尚无检查点';                               // 仅 missing 走这条
```

关键不变量：

- 数据**只**来自 `resolveUsableCheckpointForTarget()` 的同一次判断；
- 下游（`buildContext` trace、Renderer trace、coverage、entity weighting）**不**再读取数据库来获取原因；
- 未来 / 同位置 Checkpoint 仍然 `prepared.checkpoint = null`、仍然不注入、仍然不参与人物实体加权、coverage 仍然从 `-1` 重新规划；
- preview 仍然不调用 LLM；
- generation 的 hardDue 行为保持原样。

## 12. APK 验证脚本的全部硬断言

`scripts/verify-release-apk.ps1`（`$ErrorActionPreference = 'Stop'`，任一不一致 throw 并返回非零）：

| 检查项 | 断言 |
| --- | --- |
| APK 文件存在 | `Test-Path` 为真，否则 `throw "APK not found at expected path: ..."` |
| APK 文件名 | 严格等于 `ShineWriter-V<versionName>-release.apk`（V2.5.14 → `ShineWriter-V2.5.14-release.apk`） |
| APK 路径 | 必须在 `dist/apk/release/` |
| 版本元数据来源 | `src/constants/version.json`（权威）+ `package.json`（交叉校验） |
| apksigner 退出码 | `0`，否则 throw |
| apksigner `Verified` | `true`，否则 throw |
| apksigner `Verified using v2 scheme` | 严格 `true`，否则 throw |
| apksigner `Number of signers` | 严格 `1`，否则 throw |
| apksigner 证书 SHA-256 | 大小写/冒号无关比较，严格等于 `017b3fbed4001083f2f70a0c51e8e463322df66b095e1c3a476fdd0d86dc2a0a`，否则 throw |
| zipalign 退出码 | `0`，否则 throw |
| zipalign 输出 | 必须包含 `Verification successful`，否则 throw |
| aapt 退出码 | `0`，否则 throw |
| aapt `package name` | 严格 `com.shinewriter`，否则 throw |
| aapt `versionName` | 严格等于 `version.json.versionName`，否则 throw |
| aapt `versionCode` | 严格等于 `version.json.versionCode`（整数比较），否则 throw |
| APK SHA-256 | `Get-FileHash -Algorithm SHA256` 输出到汇总 |
| 汇总输出 | APK 路径 / 文件大小 / SHA-256 / 证书 SHA-256 / signer 数量 / APK Signature Scheme / zipalign 状态 / package name / versionName / versionCode |

明确禁止（脚本中均不存在）：

- Debug 签名兜底；
- 新建 keystore；
- 修改固定正式证书；
- 输出签名密码；
- 将密码/keystore 写入仓库。

PowerShell 解析容错：

- `\r\n` → `\n` 归一化（容忍 Windows 换行）；
- 字段匹配用 `Trim()` + 正则（容忍 Build Tools 小版本空格差异）；
- 证书比较走 `ConvertTo-NormalizedHash`（去冒号 + 小写）；
- 路径用 `Resolve-Path -LiteralPath`（容忍空格）。
