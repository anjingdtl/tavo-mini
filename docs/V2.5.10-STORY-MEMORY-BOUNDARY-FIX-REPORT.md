## 1. 极小 Token 预算超限

### 问题

`selectCandidatesWithinTokenBudget()` 在预算极小时可能对**整行**（前缀+正文）做 `clipTextToTokenBudget`，再从截断结果中剥离前缀写入 `candidate.text`。若截断切进前缀，外层 `formatMemoryCandidateLine()` 会重新拼完整前缀，最终注入文本可能 **> budgetTokens**。

### 修复

- 抽出 `formatMemoryCandidatePrefix()`，与 `formatMemoryCandidateLine()` 共用同一前缀格式。
- 预算函数在「尚无入选、允许截断首条」时：
  1. 先用完整前缀的 `estimateTokens(prefix)` 扣减；
  2. `prefixCost > remaining` → 跳过该候选（全部跳过则返回空）；
  3. 仅对**正文**按 `remaining - prefixCost` 截断；
  4. 再以 `formatMemoryCandidateLine` 等价字符串校验 `finalCost <= remaining`（防非可加边缘）；
  5. 中间超长候选仍跳过并尝试后续更短候选。
- 正常整行拟合、优先级预算序、展示时间升序行为不变。

### 边界测试

| 场景 | 期望 | 结果 |
| --- | --- | --- |
| `budgetTokens = 1 / 5 / 10` | 不超预算；典型前缀成本 > 10 时返回空 | PASS |
| 预算 < 完整前缀 Token | 空结果 | PASS |
| 预算刚好容纳前缀 + 少量正文 | 完整前缀保留，正文可截断，`estimateTokens(line) <= budget` | PASS |
| 第一候选超长 | 前缀完整，正文截断 | PASS |
| 多档预算汇总 | `estimateTokens(memoryText) <= budgetTokens` | PASS |

## 2. Story Memory 实体词重复计算

### 问题

`contextBuilder` 已调用 `collectStoryRetrievalTerms()` / `findActiveStoryTerms()`，但 `scoreMemoryCandidates()` 内部再次 collect + find。

### 修复

- 新增可选参数 `precomputed?: PrecomputedStoryScoringTerms | null`（`storyTerms` + `activeTerms`）。
- 省略时保持旧行为（内部自行 collect/find），兼容全部现有调用与测试。
- `contextBuilder` Episodic V2 路径：collect → find → `scoreMemoryCandidates(..., precomputed)` → hybrid select → 优先级预算 → 时间序展示。
- 无全局缓存、无可变共享状态；`storyState = null` 时仍正常（空 terms，无实体加权）。

### 测试

| 场景 | 结果 |
| --- | --- |
| 预计算路径与旧调用路径评分 `toEqual` | PASS |
| 传入 precomputed 且 `storyState = null` 时与有 state 的 legacy 一致 | PASS |
| `buildMemoryContext` 中 `collectStoryRetrievalTerms` spy 只调用 1 次 | PASS |
| null story memory 无实体加权 | PASS |
| 30 / 100 / 300 章性能 soft budget | PASS（`longStoryRecallRegression` 3/3） |

## 7. 实现摘要
