## 3. 八项问题的具体修复

### 3.1 统一所有 Episodic 路径的 Token 安全预算

`assembleMemoryContextFromIdf` 删除旧整行截断预算循环。空查询、legacy（`EPISODIC_RETRIEVAL_V2_ENABLED=false`）、非空 V2 与 IDF 空回退均产出 `ScoredMemoryCandidate[]` 后统一：

```ts
selectCandidatesWithinTokenBudget() → orderCandidatesForDisplay() → formatMemoryCandidateLine()
```

规则保持：预算 < 完整前缀 → 空；首条超长仅截正文；中间超长跳过后续；`estimateTokens(memoryText) <= budgetTokens`；展示章节位置升序。

### 3.2 Story Memory Renderer 硬 Token 上限

`renderStoryMemoryForContext` 将主线冲突/线索/伏笔/锚点/完成节点拆成可选择条目，逐项 `tryAdd` 并重算 Token。最终硬保护：

```ts
estimateTokens(result.text) <= budgetTokens
```

极小预算可返回安全截断前缀或空文本；不扩大默认 `storyStateBudgetTokens`；不改 Schema/数据结构。

### 3.3 人物与关系预算优先级

选择顺序：

1. 当前相关人物  
2. 当前相关人物之间的关系  
3. 其他最近变化人物  
4. 其他关系  
5. 主线条目  

关系双方显示仍为「姓名[ID]」。用户写作涉及林岚/周恪时，两人关系优先于大量无关人物卡。

### 3.4 `topK < 5` 选择顺序

1. 按 `finalScore` 取 Top-K  
2. 若不含最近有效章，用最近章替换最低分  
3. 返回数组再按分数排序供预算  
4. `topK=1`：默认最高分；全 0 分（空查询/零信号）取最近章  

### 3.5 统一人物实体命名空间

```ts
CharacterTermOwner { characterId, canonicalName, term, normalizedTerm, type }
normalizedTerm → CharacterTermOwner[]
```

- ASCII 统一小写  
- canonical 与 alias 同一命名空间  
- 多 characterId 歧义不自动激活  
- 最长词优先 + 区间占用，禁止「林」误激活当「林岚」已命中  
- 激活/去重/组合奖励用 `characterId`  

### 3.6 Story Memory 加入用户本次写作要求

`renderStoryMemoryForContext` / `buildStoryMemoryContext` 增加 `retrievalUserPrompt`；`buildContext` 传入真实写作要求。扫描文本 = 标题 + 概要 + 正文 + 用户要求；人物相关性复用统一命名空间（非简单 alias includes）。

### 3.7 IDF 为空回退最近摘要

`buildMemoryContextWithIdf` 在 `idf.size === 0` 时改为最近有效 `memory_summary` → 统一预算 → 时间序展示。不重新调 API、不阻断生成；空摘要仍过滤；raw Pending Bridge 排除逻辑不变。
