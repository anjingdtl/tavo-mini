## 3. CL-01 ~ CL-12 逐项验真结论

### CL-01（P0）safe_retry 真实生产链路 —— 已关闭 ✅

**复现证据（修复前失败测试）**：`__tests__/cl01SafeRetryRealChain.test.ts` 驱动**真实** `reconcilePipelineTask`（真实 in-memory SQLite 全量 schema + 真实仓储 + 真实 pipelineTaskStore，仅替换 LLM 网络出口）：

```
LLMRequestError(safe_retry) → runStageAttempt 真实写 pipeline_stage_attempts=safe_to_retry+nextRetryAt
→ persistStage 真实写 checkpoint draft=failed → task failed
→ resume → determineNextPipelineAction 返回 blocked(STAGE_FAILED)（retry disposition 从未被消费）
→ 任务永久 failed —— 修复前测试稳定失败
```

**根因**：`reconcilePipelineTask` 主循环先处理 `blocked(STAGE_FAILED)`，`maybeAutoRetryStage` 只在非 blocked 的 run_* action 上可达；而 `determineNextPipelineAction` 对 failed checkpoint 一律返回 STAGE_FAILED → 自动重试不可达（死代码）。既有的 BN-01 测试用 mock runner 手工写 attempt/checkpoint，绕过了真实 reconcile 链路，掩盖了该缺陷。

**修复**（`src/services/pipeline/determineNextPipelineAction.ts` + `reconcile.ts`）：
- 新增纯函数 `determineRetryDisposition(attempt)`：safe_to_retry/rate_limit 未到期 → `wait_retry`；到期且 ≤3 次 → `retry_now`；超限 → `manual_pause`；outcome_unknown → `manual_confirm`（绝不自动重试）；其他 → `fail`。
- reconciler 在 `blocked(STAGE_FAILED)` 之前消费 disposition：等待（≤15s 有界）→ 到期重置 checkpoint=pending（`bumpAttempt`）→ 同 loop 重跑；manual_* 以区分消息失败。

**修复后结果**：真实链路 `LLM error → attempt=safe_to_retry → checkpoint=failed → resume → disposition=retry_now → 重跑（复用同一 requestFingerprint）→ completed`。7 个测试全绿（含 outcome_unknown 不自动重试、纯函数全分支、最大重试上限）。90 个流水线/批次回归测试全绿。

### CL-02（P0）初始化失败绝不进入主界面 —— 已关闭 ✅

**复现证据**：`__tests__/cl02StartupFailRender.test.tsx` mock `openDatabase` 抛 `SQLITE_CANTOPEN` → render App → 修复前渲染树出现 NavigationContainer/TabNavigator 结构（主界面空列表），错误页不可见。

**修复后结果**：错误页可见、主界面零渲染；App/启动相关 4 个套件全绿。

### CL-05（P1）串行 LeaseSession 续租 —— 已关闭 ✅

**复现证据**：`cl05LeaseSession.test.ts` —— 60s TTL 的 batch lease 只在状态机每步续租；120-180s 单章请求期间无心跳 → lease 过期 → 第二 executor 可抢占（修复前集成测试中 120s 后 lease 已过期，`o2` 抢占成功）。

**根因**：`reconcileMultiChapterBatch` 长请求期间无续租机制（BN-09/10 曾删除 setInterval 心跳以避免 rowVersion 竞态，但留下了过期窗口）。

**修复**（`src/services/multiChapterBatch/leaseSession.ts` + `reconcileMultiChapterBatch.ts`）：`BatchLeaseSession` —— TTL/3 心跳、renew 串行化（renewChain，同一时间最多一个 CAS）、每次读最新 rowVersion、CAS 失败立即 `lost=true`（fail-closed，lost 后禁止新请求）、`stop()` 清理 timer 并等待在飞 renew、stop 后绝不回写。`run_pipeline`/`resume_pipeline` 期间真实驱动心跳，run 结束后 `assertOwned()`。

**修复后结果**：6 个测试全绿（120s 长请求续租、第二 executor 抢占、stop 后不回写、串行化 maxInFlight=1、最新 rowVersion、集成 120s 心跳 + o2 抢占失败）。批次回归全绿。

### CL-06（P1）批次预算真实硬门禁 —— 已关闭 ✅

**复现证据**：`cl06HardBudgetGate.test.ts` 驱动真实 `reconcilePipelineTask` + `batchBudgetGate` —— 修复前 `estimatedInput(297) + used(0) > maxInput(200)` 不拦截（旧门禁只查 `used >= cap`），请求照发且 attempt 行产生；attempt 失败后 `used_llm_calls` 保持 0（adoption 前不更新）。

**根因**：`assertBatchBudgetAvailable` 只比较 `used >= cap`（不含 upcoming）；`used_*` 只在整章 adoption 后由 `setBatchUsageFromRuns` 更新。

**修复**（`src/services/pipeline/reconcile.ts`）：
- 每次请求前从 `pipeline_stage_attempts` 实时聚合（幂等 SET），判断 `used + upcoming <= cap`：calls +1 / input + 编译预估 / output + 预留输出。
- 超限在 HTTP 请求前抛 `BatchBudgetExceededError`（零 attempt 行、零账单），批次落 `paused_batch_budget`。
- attempt 终态（成功/失败分类）后立即 `refreshBatchUsage`。
- `BatchBudgetExceededError` 不再被 reconcile 外层 catch 吞掉（否则批次永远进不了 `paused_batch_budget`）；阶段 catch 对预算错误不写 failed checkpoint。

**修复后结果**：3 个测试全绿（input 门禁零账单、attempt 实时入账、calls 门禁二次阻断）。40 个批次回归全绿。

## 16. 剩余风险

1. **真机 LLM 调用证据缺失**（N01/N02/N06/N07/N08）：无可用模型 API key，AI 写 N 章在真实模型上的端到端表现未在设备验证；自动化已覆盖全部关键状态转换，但模型服务可用性/网络/计费行为未真机实测。
2. **CL-12 远端 CI 未建立**：无远端 gate，回归依赖本地执行。
3. **模拟器 debug 版触摸交互异常**（release 版正常）：debug APK 在模拟器上 UI 自动点击不响应（项目卡片），影响 debug 版 UI 自动化，已用 DB 级抽查与 release 版交互替代。
4. **V2.11.24 覆盖升级路径未执行**（APK 不可得，以 V2.11.22 替代，更严格）。
5. **16KB 页面兼容告警**：系统提示若干 so 库未 16KB 对齐（RELRO），应用以兼容模式运行（非阻断，Android 16 设备建议后续处理）。
6. Story Memory 标记在原子 adoption 后为事务外 best-effort（幂等 SET 语义，崩溃重跑会重新标记，等价幂等 outbox，但非严格事务成员）。
7. `used_*` 聚合在聚合失败时静默降级为读取值（attempt 行仍为审计源，下一请求前重试聚合）。
