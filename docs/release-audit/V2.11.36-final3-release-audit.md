## 3. Frozen Context 修复前复现（F3-01，真实 SQLite 失败测试）

新增 `__tests__/f301BatchResumeFrozenContext.test.ts`：真实 sql.js 内存库 + 真实 batch store + 真实 batch/pipeline 状态机，仅 mock `callLLMResult`（LLM 网络出口）。

场景：draft/review/factCheck checkpoint=succeeded（有输出与 token）、proof=failed、batch=paused_timeout_unknown、item=outcome_unknown、active_pipeline_task_id 指向同一 task、input_fingerprint=`fp-original`、pipeline_context_json=完整有效 V2 snapshot（生产 serializer 生成，hash 天然匹配）。

修复前运行测试（真实调用 `store.resume(batchId)` 走完整 reconcile）：

```
expect(after.input_fingerprint).not.toBeNull()
Received: null        ← 失败：resume 后 fingerprint 被清空
```

同一断言序列中 `pipeline_context_json` / `pipeline_context_hash` / `pipeline_context_version` 全部被写为 NULL，任务转 interrupted 后状态机判定 `TASK_NOT_RECOVERABLE`（`determineNextPipelineAction`：`!hasDraftContext && !hasExecutionSnapshot` → blocked），用户已付费的 draft/review/factCheck 全部作废。

## 4. 根因

`src/store/multiChapterBatchStore.ts` 的 `resume()`（F2-07 的"确认后继续"路径）在存在 succeeded checkpoint 时调用全量 `savePipelineTask()` UPSERT：

```ts
await savePipelineTask({ id: taskId, targetType, targetId, status: 'interrupted',
  stageResults: [], finalText: null, error: null, createdAt, updatedAt, resolvedAt: null });
// 未传 inputFingerprint / pipelineContextJson / pipelineContextVersion / pipelineContextHash
```

`pipelineTaskRepository.savePipelineTask()` 是 `ON CONFLICT(id) DO UPDATE` 全列 UPSERT，未传字段全部落为 NULL → frozen execution/context 丢失 → `TASK_NOT_RECOVERABLE`。对照 `PipelineResultScreen.handleResumeFailed`（F2-07 单章路径）用的是裸 `UPDATE pipeline_tasks SET status='interrupted'`，不存在此问题——Batch 路径是唯一破坏点。

## 5. 修改方式

- **新增** `pipelineTaskRepository.updatePipelineTaskResumeState(taskId)`：职责单一的有目标 UPDATE，只允许修改 `status='interrupted'`、`error=NULL`、`resolved_at=NULL`、`resolved_action=NULL`、`updated_at=now`；严格保留 `id / target_type / target_id / created_at / stage_results / final_text / input_fingerprint / pipeline_context_json / pipeline_context_version / pipeline_context_hash` 原样。影响行数必须为 1，否则抛错（fail-closed）。
- **修改** `multiChapterBatchStore.resume()`：`savePipelineTask({...})` 替换为 `updatePipelineTaskResumeState(taskId)`。`savePipelineTask` 的通用语义未改动（其余调用方语义不变）。
- 不改 `determineNextBatchAction` / `reconcileMultiChapterBatch` / `resumePipeline` / `reconcilePipelineTask` 任何状态机逻辑；不重编译 frozen context。

Resume 原则保持：同一 Task + 同一 Frozen Context + 同一 Input Fingerprint + 成功 Stage 不重跑 + 只重跑失败/中断 Stage。

## 10. Batch → Pipeline → Adoption 完整链（穿透测试断言）

`store.resume` → DB re-arm（item=running_pipeline / batch=running）→ `reconcileMultiChapterBatch` → `determineNextBatchAction`（taskStatus=interrupted → resume_pipeline）→ `resumePipeline` → `reconcilePipelineTask` → `determineNextPipelineAction`（只 claim proof）→ LLM 出口成功 → proof succeeded → task completed → Atomic Adoption → item succeeded。最终断言：

```

batch item      = succeeded
chapter.content = adopted revision.content
item.adoptedRevisionId = pipeline revision.id（source='pipeline'）
task resolved_action = accept
```

## 11. Draft-only 失败路径保护（不得改坏）

- **Batch 无成功 checkpoint**：resume 解绑旧 task（activePipelineTaskId=NULL）→ 创建全新 run → 从 draft 完整重跑 → adoption 成功；旧 task 的 frozen context 原样保留（历史审计不丢）。测试断言 LLM 调用恰 1 次（draft_only 模式）→ task completed → batch completed。
- **结果页"重新尝试"（同 task）**：draft failed + 无 succeeded stage → `resetFailedStageCheckpointsForResume` + 裸 SQL 仅改 status + `registerPersistedTask`（保留 context 字段）+ `resumePipeline` → 从 draft 重跑完整流水线 → completed；`pipeline_context_json/hash` 保留、fingerprint 非空、attempt 只新增 draft 恢复一次。

## 22. 结论

**B：核心版本允许公开发版，AI 写 N 章继续默认关闭（`multi_chapter_batch_enabled=false` 不修改）。**

判定依据：
- Frozen Context Resume P1 已关闭（失败测试 → 定向修复 → 穿透测试全绿）→ AI 写 N 章具备修复条件，但 **Feature Flag 默认值未改**，由 Release Owner 决定。
- 核心 Pipeline / 数据安全 / Migration 无回归（§17 全量 Gate 通过，覆盖升级数据保留）。
- Batch resume 设备端 final-completed 一致性由 R1（真实网关 503 + 恢复完成）+ 穿透测试共同证明；R3 的 proof 重跑因模拟器网络抖动以 outcome_unknown 收尾（分类正确），未影响结论。
- device-level safe_retry（503 + Retry-After → safe_to_retry）设备实测通过；自动重试闭环由 cl01 真实链路测试证明。

## 23. Remaining Risks / Follow-ups

1. **R2 暂停入口 UI 依赖**：单章编辑页"停止"按钮依赖页面 generating 状态，导航切换后按钮不可见（只能去任务中心）；Android Alert 4 按钮限制导致"从上次失败阶段继续"弹窗中"继续"按钮被丢弃（仅剩 取消/查看任务详情/从头开始）——建议后续改为自定义对话框或任务中心为主要恢复入口（P2）。
2. **模拟器环境稳定性**：5556 长时间多轮 force-stop 后 uiautomator dump 周期性不可用（20s 超时快速失败已缓解卡死，但会中断 UI 驱动）；建议换 4KB 常规镜像或定期重启（P3，工具链）。
3. **Android-MCP 稳定性**：uiautomator dump 在 App 转场/动画期间不 idle 导致工具超时；已修（dump 超时 90s→20s + capture 串行化），需重启 opencode 生效；心跳保持建议在 MCP 包装层加进程级看门狗（P3，工具链）。
4. **R3 设备最终 completed**：模拟器网络抖动导致最后一次 proof outcome_unknown，未在设备上演示 resumed-proof → completed 的最终帧（穿透测试与 R1 已覆盖该路径）；下一轮可用更稳定网络复验（P3）。
5. **历史 lint 162 warnings**：未清理（按 Final-3 范围纪律，记录不处理）。
6. 上一轮报告将 network_error/outcome_unknown 记录为 safe_retry 的分类错误已在 §14 修正，后续审计以 attempt.failure_class 为准。
