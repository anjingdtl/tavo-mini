# V1.6.2 Backlog UX 打磨：进度反馈、结果弹窗、备份布局

> 日期：2026-06-14
> 状态：已确认，待实施
> 目标版本：V1.6.2
> 关联 spec：`docs/superpowers/specs/2026-06-14-draft-crashfix-and-toolbar-relayout-design.md`

## 1. 背景

V1.6.1 修复了草稿预览闪退与章节编辑工具栏重排。本 spec 落地 V1.6.1 progress.md 末尾记录的 3 个 backlog：

1. **写作管线进度反馈缺失**：点击"续写"后只有按钮文案变"续写中…"，缺少阶段级进度反馈，用户感知不到 LLM 在干活。
2. **流水线结果不会自动出现**：流水线完成后只是 navigate 到 `PipelineResult` 全屏页面，用户要手动进入"草稿预览"采纳；期望在 ChapterEditor 之上以 Modal 弹结果。
3. **备份中心"创建备份"按钮被备份卡片视觉遮住**：FlatList 列表项与 createRow 同行布局时被遮。

约束与 V1.6.x 一致：Android-only、单用户、本地优先，不引入新依赖，不改数据库 schema。

## 2. 成功标准

### 2.1 进度反馈

- 点击"续写"后 ≤ 1 秒内，ChapterEditor 顶部出现进度条（`ActivityIndicator` + 当前阶段名 + 已用时长）。
- 阶段切换时（draft → review → factCheck → proof），进度条文字平滑切换，无明显闪烁。
- 流水线成功完成时，进度条消失，结果 Modal 自动弹出。
- 流水线失败时，进度条消失，Alert 提示，**不弹**结果 Modal。
- 进度条在 `focusMode = true` 时不显示（专注模式只关心写作本身）。
- 进度条在 `generating = false` 时不渲染（不影响章节列表性能）。

### 2.2 结果 Modal

- 流水线成功后，ChapterEditor 之上弹出 Modal 包裹 `PipelineResultScreen`。
- Modal 内可正常查看阶段详情、采纳结果、放弃。
- 点击"采纳"成功 → Modal 关闭 + 章节内容刷新 + 状态显示"已保存"。
- 点击"放弃"或 Modal 外部/返回键 → Modal 关闭 + 章节内容不变化 + 草稿仍保留在草稿预览页可后续采纳。
- 流水线失败时**不弹** Modal（仍走原 Alert 路径）。
- 关 Modal 后用户仍停留在 ChapterEditor，**不**自动 navigate 任何地方。
- `presentationStyle = "overFullScreen"`，背景半透明遮罩（`rgba(0,0,0,0.6)`）。

### 2.3 备份中心布局

- 滚动备份列表时，"创建备份"按钮固定在 Header 下方，不被任何备份卡片遮住或视觉重叠。
- "创建备份"按钮有清晰的视觉边界（底部分隔线 / 阴影），与下方列表明显区分。
- 备份列表条目再多也能完整滚动到底。
- 备份卡片本身布局、恢复 / 删除按钮位置不变。

### 2.4 工程质量

- `npm test -- --runInBand` 全部通过。
- `npm run lint` 无 error。
- 不引入新 npm 依赖。
- 不修改 `package.json` 已有 `version` 之外的任何字段。

## 3. 不在本设计范围

- 进度条显示流式字符数 / token 计数（用户已选"简单 Loading 转圈"）。
- 流水线结果触发后自动跳转（用户已选"在 ChapterEditor 上弹 Modal"）。
- 备份中心的搜索 / 排序 / 筛选。
- 备份列表项的合并 / 详情展开。
- 流水线阶段预估剩余时间。
- 任何 native 模块或 Android 端改动。

## 4. 总体架构

### 4.1 新增组件边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `components/PipelineProgress.tsx` | 渲染 ActivityIndicator + 阶段名 + 已用时长 | 不持有业务状态，只接收 props |
| `components/GenerationResultModal.tsx` | 包装 React Native `Modal` + `PipelineResultScreen` | 不实现采纳逻辑，复用 `PipelineResultScreen` |

`pipelineRunner.runChapterPipeline` 的 `onStageUpdate` 钩子扩展为更丰富的 `onStage` 回调（向后兼容旧 `() => {}` 调用点）。

### 4.2 数据流

```text
用户点击"续写"
  -> ChapterEditor.executeRunPipeline
     -> onStage({ stage: 'draft', label: '草稿中...', startedAt: Date.now() })
     -> PipelineProgress 渲染
  -> runChapterPipeline(taskId, chapter, onStage)
     -> 各阶段 setTaskStatus / updateTaskStage
     -> 每个阶段开始时 onStage({ stage, label, startedAt })
  -> saveDraftAndComplete
  -> ChapterEditor 收到最终结果
     -> setShowResultModal(true)
     -> GenerationResultModal 渲染 PipelineResultScreen
  -> 用户在 Modal 中"采纳"或"放弃"
     -> 采纳：createRevision + updateChapter + onAdopted() 回调
     -> 放弃 / 关闭：onClosed() 回调
  -> ChapterEditor setShowResultModal(false)
```

## 5. 设计：动态进度条

### 5.1 组件

`src/components/PipelineProgress.tsx`：

```tsx
interface Props {
  stage: 'idle' | 'draft' | 'review' | 'factCheck' | 'proof';
  startedAt: number;  // Date.now()
  visible: boolean;
}

const STAGE_LABELS: Record<Props['stage'], string> = {
  idle: '准备中...',
  draft: '草稿中...',
  review: '点评中...',
  factCheck: '事实检查中...',
  proof: '打磨中...',
};
```

**渲染内容：**
- `ActivityIndicator`（color = `theme.colors.accent`）
- 当前阶段文字（color = `theme.colors.textSecondary`，fontSize 13）
- 已用时长：`(Date.now() - startedAt) / 1000` 秒，整数显示，文字带"s"后缀
- 容器：水平 row，`gap: spacing.sm`，`padding: spacing.sm`，`backgroundColor: theme.colors.surface`，`borderBottomWidth: hairline`，`borderColor: theme.colors.border`

**已用时长刷新：** 使用 `useEffect` + `setInterval(..., 1000)`，组件卸载时 clearInterval。

### 5.2 接入 ChapterEditor

当前 [ChapterEditor.tsx:224](file:///workspace/src/screens/ChapterEditor.tsx#L224) 调用：

```ts
await runChapterPipeline(taskId, chapter, () => {});
```

改为：

```ts
const startedAtRef = useRef<number>(Date.now());
await runChapterPipeline(taskId, chapter, (info) => {
  // info: { stage, label, startedAt }
  startedAtRef.current = info.startedAt;
  setCurrentStage(info.stage);
  setProgressVisible(true);
});
```

新增 state：

```ts
const [currentStage, setCurrentStage] = useState<PipelineStageName | 'idle'>('idle');
const [progressVisible, setProgressVisible] = useState(false);
```

进度条位置：[ChapterEditor.tsx](file:///workspace/src/screens/ChapterEditor.tsx) 的 `Header` 之后、`!focusMode && (...)` 之前。

`onStage` 回调函数在 `runChapterPipeline` 中以如下形式被调用（保持现有调用点语义，只扩展第二个参数）：

```ts
export async function runChapterPipeline(
  taskId: string,
  chapter: Chapter,
  onStageUpdate?: (info: { stage: PipelineStageName | 'idle'; label: string; startedAt: number } | string) => void,
): Promise<void> {
  // 兼容旧 string 调用点
  const emit = (info: { stage: PipelineStageName | 'idle'; label: string; startedAt: number }) => {
    if (!onStageUpdate) return;
    onStageUpdate(info);
  };
  // ... 各阶段开始时：emit({ stage: 'draft', label: '草稿中...', startedAt: Date.now() });
}
```

**backward compatibility：** 因为 `onStageUpdate` 当前所有调用点都传 `() => {}`，扩展参数后这些调用点不受影响。本设计**只新增**调用点，不修改 `() => {}` 的旧调用点。

### 5.3 行为细节

- 进入 generating 时（`setGenerating(true)`）显示进度条。
- 流水线成功完成（`finishedTask?.status === 'completed'`）时，进度条消失，结果 Modal 同步弹出。
- 流水线失败时，进度条立即消失（`setProgressVisible(false)`），走原 Alert 路径。
- `unmount` 组件时清除 setInterval。

## 6. 设计：流水线结果 Modal

### 6.1 组件

`src/components/GenerationResultModal.tsx`：

```tsx
interface Props {
  visible: boolean;
  taskId: string;
  onClosed: () => void;
  onAdopted?: (acceptedText: string) => void;
}
```

内部使用 React Native 的 `Modal` 组件 + `presentationStyle="overFullScreen"` + `animationType="slide"` + 半透明背景。

复用 `PipelineResultScreen`，但需要它支持非路由模式（`taskId` 来自 props 而非 `useRoute`）。

### 6.2 PipelineResultScreen 改造

当前 [PipelineResultScreen.tsx:45-60](file:///workspace/src/screens/PipelineResultScreen.tsx#L45-L60) 强依赖 `useRoute` 拿 `taskId`。改造为：

```ts
export const PipelineResultScreen: React.FC<{
  taskId?: string;           // 新增：可显式传入
  onClose?: () => void;       // 新增：Modal 模式下替代 navigation.goBack
  onAdopted?: (text: string) => void;  // 新增：采纳回调
}> = ({ taskId: propTaskId, onClose, onAdopted }) => {
  const navigation = useNavigation();
  const route = useRoute<ResultRouteProp>();
  const taskId = propTaskId ?? route.params?.taskId;
  // ...
  const handleClose = onClose ?? (() => navigation.goBack());
  // ...
  const handleAdopt = async (text: string) => {
    // 现有采纳逻辑...
    onAdopted?.(text);
  };
};
```

`onAdopted` 触发时让 Modal 调用方（ChapterEditor）做两件事：
- 刷新章节内容（`await loadChapter()`）
- 关闭 Modal（`setShowResultModal(false)`）

### 6.3 章节内容刷新

`ChapterEditor` 已有 `loadChapter` 函数（[ChapterEditor.tsx:56-58](file:///workspace/src/screens/ChapterEditor.tsx#L56-L58)），Modal 采纳回调里调一次即可。

### 6.4 行为决策

| 用户操作 | Modal 反应 | ChapterEditor 反应 |
|---|---|---|
| 流水线成功 | 弹 Modal | 进度条消失 + `setShowResultModal(true)` |
| Modal 内点"采纳" | 调 onAdopted | `loadChapter()` + 关闭 Modal + Alert 提示"已采纳" |
| Modal 内点"放弃" | 调 onClose | 关闭 Modal，章节不变 |
| Modal 返回键 / 点遮罩 | 调 onClose | 关闭 Modal，章节不变 |
| 流水线失败 | 不弹 Modal | 进度条消失 + 走原 Alert.alert 路径 |

## 7. 设计：备份中心布局修复

### 7.1 现状

[BackupCenterScreen.tsx:181-211](file:///workspace/src/screens/BackupCenterScreen.tsx#L181-L211) 当前布局：

```tsx
<Screen>
  <Header ... />
  <View style={styles.createRow}>
    <Button label="创建备份" ... />
  </View>
  {loading ? ... : backups.length === 0 ? ... : (
    <FlatList ... />
  )}
</Screen>
```

`Screen` 容器 `flex: 1`，Header + createRow 是普通子元素，FlatList 也是普通子元素。**没有给 createRow 设 elevation / zIndex / backgroundColor / borderBottom**，FlatList 向上滑时卡片视觉上与 createRow 重叠。

### 7.2 修复

`styles.createRow` 改造：

```ts
createRow: {
  paddingHorizontal: spacing.lg,
  paddingTop: spacing.md,
  paddingBottom: spacing.md,
  backgroundColor: theme.colors.surface,  // 新增：与 Screen 背景不同
  borderBottomWidth: StyleSheet.hairlineWidth,  // 新增：视觉分隔
  borderBottomColor: theme.colors.border,       // 新增
  elevation: 2,    // 新增：Android 浮起
  zIndex: 2,       // 新增：确保不被 FlatList 覆盖
},
```

`FlatList` 的 `contentContainerStyle` 改为：

```ts
list: {
  padding: spacing.lg,
  paddingTop: spacing.md,  // 新增：与 createRow 拉开间距
  paddingBottom: 96,
},
```

可选优化：把 createRow 升级为 sticky header（用 FlatList 的 `ListHeaderComponent`），让它随列表一起滚动但保持视觉位置固定在第一行。但本设计**不**做 sticky，第一版最小修复即可。

- 空状态、加载状态不变。
- 颜色变量沿用主题色。
