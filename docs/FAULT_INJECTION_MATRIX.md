# 故障注入验证矩阵

本矩阵对应 `__tests__/faultInjectionMatrix.test.ts`。每个场景都定义用户反馈、数据库状态、重试与备份策略、临时文件/任务清理和诊断字段。真实设备长杀、磁盘耗尽与厂商内存回收仍需在发布设备矩阵中执行；这里的 Jest 测试先锁定产品必须保持的恢复契约。

| #   | 故障                      | 用户看到什么                      | 数据库状态         | 可重试 / 需恢复备份        | 孤儿文件 / 卡死任务 | 诊断信息                         |
| --- | ------------------------- | --------------------------------- | ------------------ | -------------------------- | ------------------- | -------------------------------- |
| 1   | migration 第三条 SQL 失败 | 升级失败，原数据保留              | 升级前 Schema      | 可重试；保留升级前备份     | 否 / 否             | 版本、语句序号、rollback         |
| 2   | 恢复中途失败              | 恢复失败，可换其他备份            | 原数据库不切换     | 可重试；不需要额外恢复     | 否 / 否             | 恢复阶段、事务回滚、备份路径     |
| 3   | 磁盘空间不足              | 空间不足，清理后重试              | 最近一次已提交状态 | 可重试；不需要恢复         | 否 / 否             | `ENOSPC`、目标路径、请求字节数   |
| 4   | 备份文件损坏              | 备份不可读，原库不变              | 不变               | 可换备份；不执行恢复       | 否 / 否             | 解析错误、路径、格式版本         |
| 5   | checksum 错误             | 校验失败，不执行恢复              | 不变               | 可换可信备份；不接受原文件 | 否 / 否             | 算法、期望值、实际值             |
| 6   | 自动保存时杀死 App        | 重启后加载最近已提交内容          | 最近一次已提交状态 | 可继续编辑重试；不需恢复   | 否 / 否             | revision、提交时间、dirty 状态   |
| 7   | 迁移时杀死 App            | 下次启动继续升级或恢复            | 升级前 Schema      | 可重试；必要时用升级前备份 | 否 / 否             | 版本、启动恢复、保护性备份       |
| 8   | 恢复时杀死 App            | 启动校验后继续使用原数据或重试    | 原数据库不切换     | 可重试；保留保护性备份     | 否 / 否             | 原子恢复、保护性备份、启动校验   |
| 9   | GGUF 导入时杀死 App       | 导入未完成，可重新选择原文件      | 最近一次已提交状态 | 可重试；不需恢复           | 临时文件清理 / 否   | importId、staging 路径、清理结果 |
| 10  | 本地模型生成内存不足      | 本次生成停止，建议降低模型/上下文 | 最近一次已提交状态 | 可重试；不需恢复           | 否 / 否             | 内存压力、模型 ID、原生错误码    |
| 11  | 在线模型请求断网          | 网络失败，正文不变                | 最近一次已提交状态 | 网络恢复后可重试；不需恢复 | 否 / 否             | `network_error`、场景、脱敏 URL  |
| 12  | TTS 播放中切后台          | 朗读保持可见，可继续或停止        | 不变               | 可继续/重试；不需恢复      | 否 / 否             | App 状态、TTS 会话、前台服务     |

## 执行方式

```bash
npx jest __tests__/faultInjectionMatrix.test.ts --runInBand --forceExit
```

发布设备矩阵还应把每个场景的 logcat、应用诊断日志、数据库快照和清理后的文件目录作为证据附在发布报告中。
