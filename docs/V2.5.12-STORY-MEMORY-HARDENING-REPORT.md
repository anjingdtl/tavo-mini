### 2.3 删除或替换的重复逻辑

| 旧模式 | 处理 |
| --- | --- |
| `record.status === 'clean' && through >= 0` 后直接注入 | 替换为 `resolveUsableCheckpointForTarget` |
| prepare 仅排除 dirty 后使用 through | 替换为 eligibility（含 future/same） |
| `findActiveStoryTerms` 内独立最长匹配循环 | 替换为 `resolveCharacterMentionsInText` |
| 候选摘要 `includesInsensitive(doc, canonical/alias)` 身份判断 | 替换为候选侧 mention resolver + ID 交集 |
| `buildActiveIdToCanonical(ids[], names[])` 平行数组 | **删除**；改用 `canonicalNameByCharacterId` |
| Renderer 先塞满全部当前人物再塞关系 | 改为高优先关系 bundle（双方卡 + 关系行）原子加入 |
| 空查询依赖 `query \|\| legacyQuery` 掩盖空串 | 显式 `queryText` 存在时尊重空串；`empty_query_recent` 模式 |

仓库扫描：生产路径注入/加权不再出现裸 `status === 'clean'` 后直接用 state。  
`storyMemoryRebuild.ts` 的 `status === 'clean'` 仅用于「重建是否已完成」判断，不属于注入/加权契约。

## 3. 六项补漏实现摘要

1. **未来 Checkpoint 隔离**：`through >= target` → `usable=false`，`checkpointThroughPosition=-1`，不注入、不加权、coverage 从 -1 重规划。  
2. **共用人物解析器**：query / candidate / Story Memory scan 同一 `resolveCharacterMentionsInText`。  
3. **显式 ID 映射**：`activeCharacters` + `canonicalNameByCharacterId`；重名李明（记者/医生）稳定。  
4. **关系预算保障**：`RelationshipBundle` 原子加入；测试构造 8 人场景下关键 `rel_lan_zhou` 可进入。  
5. **真实空查询 + 路径矩阵**：`resolveEpisodicRetrievalMode`；空 title/synopsis/content + `queryText:''` 进入 `empty_query_recent`。  
6. **版本门禁**：`npm run verify:version` 校验 package / lock / version.json / README / CHANGELOG / versionCode 规则。

## 5. 反例与固定种子

固定种子 LCG（非位运算）覆盖：

| 规模 | 结果 |
| --- | --- |
| 10 人 × 30 章 seed=42 | 确定性、无重复 ID、预算内（约 6 ms） |
| 50 人 × 100 章 seed=7 | 同上（约 33 ms） |
| 100 人 × 100 章 seed=99 | 同上（约 68 ms） |

反例审查（执行结果，非猜测）：

1. 目标章早于 Checkpoint → 不注入、coverage -1  
2. 查询/摘要不同别名 → 同 characterId 命中  
3. 两人同名 → 靠 alias 激活不同 ID  
4. 子串姓名 → 不误激活  
5. 多当前人物 → 关系 bundle 优先  
6. 预算 1/10 → 不超限  
7. 空 IDF → `empty_idf_recent` / 最近摘要路径  
8. Dirty/failed/rebuilding → 永不 usable  
9. preview → prepare 不调用 LLM（既有测试）  
10. 版本号 → `verify:version` 通过
